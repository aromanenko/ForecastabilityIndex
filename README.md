# ForecastabilityIndex

Расчёт индекса прогнозируемости для недельных рядов «магазин × товар».

- `DBA_project_ForecastabilityIndex.ipynb` — основной анализ локальных CSV из `data/`.
- `setup/DBA_project_setup.ipynb` — учебные примеры; WAPE в первом графике этого шаблона искусственный.

## Запуск

Проверено с Python 3.12. Зависимости зафиксированы в `requirements.txt`.
Для нового окружения нужен Python с модулем `venv` и поддержкой `pip`:

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
```

В текущей рабочей копии `.venv` уже подготовлено. Полный запуск обоих ноутбуков:

```bash
.venv/bin/python scripts/execute_notebooks.py
```

Каждый ноутбук выполняется последовательно в отдельном чистом ядре, выбранном
из того же Python-окружения. Ошибки останавливают выполнение. При успехе результаты
сохраняются в исходном `.ipynb`; при ошибке диагностическая копия сохраняется
в `outputs/*.failed.ipynb`. Для запуска Jupyter требуются локальные соединения с ядром.

Запуск только основного ноутбука и проверок расчётов:

```bash
.venv/bin/python scripts/execute_notebooks.py DBA_project_ForecastabilityIndex.ipynb
.venv/bin/python -m unittest discover -s tests -v
```

При интерактивном запуске выберите Python из `.venv` и выполните Restart Kernel / Run All.
Рабочая папка должна находиться внутри проекта. Предварительно запускать отдельные
ячейки или загружать файлы в Colab не требуется.

## Исправленные ошибки

- Исправлен `%import`; пути Colab и относительные пути заменены на `data/`.
  Справочник магазинов читается с разделителем `;`, даты train/test — в своих форматах.
- Значение `01Jan5999` в дате закрытия больше не удаляет действующие магазины.
  Повторная загрузка исходного train больше не отменяет фильтрацию.
- Убраны несовместимые переопределения `get_ts` и зависимость от переменных старого ядра.
- Первый шаг прогноза сравнивается со следующей неделей, а не с известным значением
  в момент прогноза. Горизонт берётся из test; пропущенные недели не сжимаются.
- Точечная WAPE считается по исходным наблюдениям; bootstrap воспроизводим.
  Нулевой спрос обрабатывается без искусственного добавления малого числа в знаменатель.
- Ряды считаются по паре «магазин × товар». Объём продаж не дублируется из-за
  перекрывающихся окон, а WAPE кластера считается по суммам ошибок и спроса.
  Нулевая WAPE попадает в Easy.
- Постоянные ряды не вызывают деления на ноль при проверке сезонности.
  Исправлена форма осей для графика с единственным числовым столбцом.
- В шаблоне добавлена загрузка локальных данных и убрана установка библиотек из ячеек.

## Ограничения методики

Успешный прогон подтверждает работоспособность расчётов, но не независимую оценку
будущего качества сегментации. Признаки сегментов рассчитаны по всей доступной
истории, включая даты исторического бэктеста. Для независимой оценки их нужно
пересчитывать только по обучающему окну.

Обычный bootstrap строк не учитывает зависимость перекрывающихся прогнозных окон;
интервалы следует считать ориентировочными. Для строгой оценки нужен временной
или кластерный bootstrap. Сезонность определяется эвристикой автокорреляции.

Финальные кластеры используют заданные пороги WAPE 50% и 75%, а не ABC-анализ,
упомянутый в первоначальном задании. Высокая WAPE наивного прогноза сама по себе
не означает невозможность получить хороший прогноз другой моделью.
